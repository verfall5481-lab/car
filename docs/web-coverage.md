# 웹 구현과 검증 범위

## 화면과 동작

| 경로 | 구현 |
| --- | --- |
| `/`, `/c/`, `/c/me` | 역할 진입, 간단 모드 픽업·루틴·진행·탑승 확인, 전화 링크와 알림 설정 |
| `/c/start`, `/c/install`, `/c/link` | 링크 코드 표시, 플랫폼별 홈 화면 안내, Android 코드 전달, 입력한 코드 검증과 익명 세션, 성인 본인 동의, 기기 전환 확인과 해지 후 재연결 |
| `/p/login`, `/p/auth/callback`, `/p/install` | 보호자 이메일 숫자 인증, 역할별 저장소, 안전한 원래 경로 복귀, 선택형 Kakao PKCE와 Turnstile |
| `/p/onboarding`, `/p/join`, `/p/family/invite` | 가족 만들기와 참여, 가입 동의, 초대 확인, QR·코드·공유 링크 |
| `/p/`, `/p/request` | 지금 할 일, 오늘·내일 일정, 보호자 본인 요청과 진행 화면, 설정이 필요한 새 가족 안내, 문자 실패 안내 |
| `/p/pickups/:id`, `/handoff`, `/location` | 픽업 상세·이벤트 기록, 차량 선택·수락·인계·거절·만료, 대신 가기, 위치 확인·저장, 출발과 5분 이내 되돌리기, 취소 사유, 회차 건너뛰기, 도착과 별도 탑승 확인 |
| `/p/routines`, `/p/routines/new`, `/p/routines/:id` | 대상·장소·타는 곳·요일·시각·기간·알림·기본 담당과 차량, 수정·비활성·예정 픽업 유지 또는 취소·보관 |
| `/p/family`, `/p/members/:id`, `/p/riders/:id`, `/p/children/:id` | 가족 목록, 관리자 이전·구성원 내보내기, 요청·운전 권한, 아이·어른 등록과 정보 관리, QR·문자 연결 및 개별 기기 해제 |
| `/p/places/:id`, `/p/places/new` | 장소·타는 곳 추가, 수정, 보관과 반경, 브라우저 위치, Kakao 지도와 검색 또는 직접 좌표 입력 |
| `/p/vehicles/pair`, `/p/vehicles/:id` | 연결 코드, 이름·운전자, 최근 차량값·거리와 부족 알림, 연결 해제 |
| `/p/notifications`, `/p/settings`, `/p/demo` | 역할별 푸시 구독·해제와 테스트 알림, 가족·내 정보·동의·로그아웃·계정 삭제, 권한 확인을 거치는 서버 데모 도구 |
| `/v/` | 기본은 브라우저 내부 차량 시뮬레이터. 요청 수락과 출발, 주차·주행, 안내 실패와 세션이 지난 콜백, 도착과 탑승, 거리와 오프라인 표시. 연결 모드에서 `VITE_LIVE_VEHICLE_SIM=true`이면 같은 차량 화면이 실제 서버의 익명 차량 주체로 동작하는 웹 차량 시뮬레이터(명세 23.8): 연결 코드·QR·보호자 연결 링크와 페어링 확인, 연결 해제와 해지 후 재연결, 피드 폴링(10초, 실패 시 30초)과 마지막 피드의 오프라인 표시, 서버 카드 종류에 따른 요청·부탁·리마인더·긴급 취소 카드, `action_id`가 붙은 출발하고 안내와 통신 재시도, 시뮬레이션 내비 결과와 새 세션 재시도, 수동 도착과 현재·이전 세션 도착 콜백, 주차 상태를 다시 보낸 뒤의 탑승·위치 확정·운전자 변경, 주행가능거리 경고 확인, 항상 데모 값인 기어·주행가능거리 업로드 |

실제 연결 모드에서 픽업 상태는 인증된 RPC로만 변경합니다. 보호자 피드는 가족별 Realtime 무효화와 주기 조회를 함께 사용합니다. 간단 모드는 진행 상태에 따라 조회 간격을 변경합니다. 간단 모드와 보호자 서비스 워커는 서로 다른 범위에서 푸시를 처리하며 다른 역할의 알림 경로와 코드가 담긴 요청 캐시를 차단합니다. 현재 위치는 브라우저에서 한 번 읽고, 선택해 요청할 때만 서버에 보냅니다.

## 검증 수준

### 2026-11-09 견본 UI 보완

- 구현은 `gpt-6.1-sol`의 `xhigh` 추론으로 분담하고, 통합 검수에서 실제 Edge 화면을 공급된 견본과 대조했습니다. 모바일 헤더·하단 탭·선택 칩·코드 입력·폼·시트와 차량의 좌우 분할·큰 버튼·완료 화면을 조정했습니다.
- SUIT Variable v2.0.5를 자체 호스팅하여 한국어 글꼴이 운영체제의 대체 글꼴에 따라 달라지는 것을 줄였습니다. 라이선스는 `NOTICE.md`에 기록했습니다.
- 최종 타입 검사와 프로덕션 빌드가 통과했습니다. 공통 상태/웹 단위 테스트 18개 및 브라우저 시나리오 10개가 통과했습니다. 브라우저 시나리오 중 새 호칭 라벨 때문에 실패한 2개는 의도된 문구에 맞게 테스트 선택자를 바꾸고 재실행했습니다.
- 실제 브라우저에서도 요청 → 보호자 수락 → 인계 제안(기존 담당 유지) → 수락 → 차량 출발 → 도착 → 사람이 누르는 탑승 확인을 검수했습니다. 390×844 모바일 배치에서 선택 칩 줄바꿈, 토글 너비, 원형 버튼 글자, 차 상세 간격을 보완했습니다.
- 비교용 실제 웹 캡처 31개와 8개 묶음은 로컬 `test-results/ui-reference-review/`에 있습니다. `index.html`에서 개별 원본을 열 수 있습니다. 긴 화면은 첫 뷰포트 캡처이며 견본의 모든 예외 상태를 캡처한 목록은 아닙니다.
- 데모 로그인/초대/알림/차 연결 화면은 명시적인 로컬 시연입니다. 실제 발송·인증·차량 연결을 수행했다고 표시하지 않습니다. 데모 루틴 기간은 기존 요일 모델을 유지하며 시작일/종료일은 실제 모드에서 편집합니다. 실제 공급자와 모바일 설치·권한·AAOS 화면은 별도 검증 대상입니다.

- 데모 Chromium 테스트는 세 탭의 요청·인계·출발·도착·탑승과 취소, 주행 중 도착과 주차 중 탑승, 모바일 지도 키보드 조작을 확인합니다.
- 연결 모드 Chromium 테스트는 Supabase 인증·RPC와 보안 확인을 모의 응답으로 재현합니다. 이메일 OTP의 상세 경로 복귀, 가족 만들기와 참여, 간단 모드 설치 링크와 성인 동의, 요청과 저장소 분리, Kakao PKCE 코드를 검증합니다.
- 단위 테스트는 실제 SQL 응답 fixture, 인계 담당 유지와 거리 불명 처리, 취소 사유와 GPS/핀 인자, 공개 키 검사, 서비스 워커 범위를 확인합니다.
- 실제 SQL 권한·잠금·스케줄·알림 큐는 [백엔드 RPC 계약](backend-api.md)과 저장소의 SQL 테스트로 별도 확인합니다.

### 2026-11-10 연결 모드 웹 차량 시뮬레이터

- `/v/` 차량 화면은 데이터와 동작을 주입받도록 바꿨습니다. 데모는 기존 브라우저 저장소 거래를 그대로 쓰고, 연결 모드는 `vehicle_get_feed`를 같은 화면 모양으로 옮긴 뒤 차량 RPC를 부릅니다. 기존 데모 Chromium 시나리오를 그대로 통과합니다.
- 연결 모드 차량 Chromium 테스트 6개는 모의 Auth·RPC 응답으로 코드 페어링과 홈 화면, `action_id`가 붙은 출발과 내비 실패 후 출발 유지·새 세션 재시도, 수동 도착과 주행 중 탑승 보류·주차 상태 재전송 뒤 탑승, 이전 세션 도착 콜백 무시, `vehicle_decline`과 모든 상태 업로드의 데모 값 표시, 오프라인일 때 마지막 피드 유지와 버튼 비활성화를 확인합니다.
- 단위 테스트는 저장소의 실제 `vehicle_get_feed` fixture로 피드 변환과 카드 선택을 확인하고, 차량 RPC 인자 이름을 마이그레이션의 함수 시그니처와 대조합니다. 화면 코드의 한글 문자열이 카피 모듈 밖에 있으면 실패하는 검사도 추가했습니다.
- 1280×720에서 페어링, 요청 카드, 가는 중, 내비 실패, 도착, 주행 중 도착, 탑승 확인, 설정 화면을 직접 캡처해 어두운 배경·큰 글자·호박색 주 버튼과 넘침 여부를 확인했습니다. 390px 폭에서는 기존 데모와 같이 차량 화면(가로 2:1, 최소 높이)이 화면보다 넓어 가로 스크롤이 생깁니다.

### 2026-11-11 경쟁에서 진 차량 안내

- 공용 상태 머신(`packages/contracts`)이 SQL의 경쟁 패배 규칙(8.3.1, V-03)을 따릅니다. 요청·루틴 카드에서 누른 "출발하고 안내"가 다른 사람이 먼저 맡은 픽업에 닿으면 `ALREADY_TAKEN`과 맡은 사람(`by`)을 돌려주고 아무것도 바꾸지 않습니다. 제안 ID가 없을 때와 가족 전체 제안의 ID일 때 결과가 같고, 보낸 사람이 있는 인계 제안의 ID만 인계 경로로 갑니다. `accept`의 경합 패배도 `by`를 돌려줍니다.
- 웹 차량 화면은 인계 카드에서만 제안 ID를 보냅니다. 요청·루틴 카드는 보내지 않습니다. 진 차량은 "엄마가 먼저 맡았어요"를 보여 주고 3초 뒤 카드를 닫습니다. 데모는 상태 머신의 `by`를 호칭으로 바꿔 쓰고, 연결 모드는 서버 응답의 `detail.by`를 씁니다.
- 적합성 시나리오 49개가 TypeScript와 SQL에서 같은 결과를 냅니다. 계약 테스트 80개(적합성 50개 포함), 웹 단위 테스트 33개, Chromium 테스트 23개, pgTAP 검사 2,698개가 통과했습니다.
- 연결 모드 차량 Chromium 테스트는 7개가 됐습니다. 추가한 테스트는 주행 중인 차가 요청 카드에서 출발을 눌렀을 때 모의 서버가 `ALREADY_TAKEN`과 `detail.by`를 돌려주면 이름이 든 안내가 뜨고 카드가 닫히며, 출발 호출을 다시 보내지 않고 안내 세션도 열지 않는지 확인합니다. 주행 중에는 피드에 오늘 목록이 없어 이름이 응답에서만 올 수 있습니다. 실제 Supabase 응답으로는 확인하지 않았습니다.

## 추가로 확인할 사항

- 실제 GoTrue/PostgREST/Realtime 구성, 이메일·문자·웹 푸시 공급자, Kakao 지도와 OAuth, Turnstile 실제 챌린지는 환경별 키와 서버 설정을 적용한 뒤 연결 시험이 필요합니다.
- iPhone Safari와 설치된 홈 화면 앱의 세션·알림·위치 권한, Android 설치 프롬프트는 실기기 확인이 필요합니다.
- 웹 `/v/`는 시뮬레이터입니다. 연결 모드 웹 차량 시뮬레이터도 실제 서버 세션에 가짜 차량 값과 시뮬레이션 내비를 쓰므로 차량 신호, NaviHelper, 주행 제한, 헤드업 알림 검증을 대신하지 않습니다. 실제 차량·Pleos SDK 검증은 [차량 검증 기록](vehicle-verification.md)에 따로 기록합니다.
- 웹 차량 시뮬레이터는 모의 서버로만 확인했습니다. 실제 Supabase의 익명 로그인·페어링·차량 RPC 왕복, 차량 화면 기준 30초 주차 판정과 서버 시각 차이는 연결 환경에서 확인해야 합니다.
- 위치 확인 시 실제 정확도 값이 피드에 없으면 추정 숫자 없이 미확정 상태를 표시합니다. 타는 곳 검색에 Kakao JavaScript SDK를 사용하며 키나 응답이 없으면 직접 좌표나 브라우저 위치를 받습니다.
- 서버 데모 모드는 관리자가 소속된 가족이 데모로 설정된 경우에만 표시합니다. 브라우저 데모의 가짜 데이터와 키를 공유하지 않습니다.
